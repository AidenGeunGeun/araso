# URL·경로 안의 영어

## 지금의 문제

세션은 `/`, `.`, `?`, `=`, `&`, `@`를 단어 경계로 보고 그 뒤 조각을 새 단어로 판단합니다. 앞이 영어라는
기울기(`contextBias`)로는 짧은 조각을 뒤집지 못합니다. 일본어를 켜면 한 조각이 가나가 된 뒤로 기호까지 전각이
되어 URL 전체가 무너집니다(`aa.com` → `ああ。cおm`, `ho@gmail.com` → `ほ＠gまいl.com`).

## 잰 것 (2026-10-19, `araso-cli --type`, 세션으로)

조각 = en_50k 상위 영어 단어 5,000개(2–8글자), 또는 두 글자 조합 676개 전부(쿼리 키, ID, 짧은 경로처럼 단어가
아닌 것).

| 자리 | 예 | 영어 단어 (끔 / 켬) | 두 글자 (끔 / 켬) |
| --- | --- | --- | --- |
| 표시 뒤: 경로 | `https://example.com/{}` | 6 / 20 | 168 / 208 |
| 표시 뒤: 쿼리 | `https://a.io/?q={}` | 6 / 20 | 168 / 208 |
| 표시 뒤: 홈 경로 | `cd ~/{}` | 6 / 20 | 168 / 208 |
| 표시 없음: 브랜치 | `git checkout fix/{}` | 6 / 20 | 168 / 208 |
| 표시 앞: 도메인 | `{}.com` | 13 / 20 | 199 / 200 |
| 표시 앞: 이메일 | `{}@gmail.com` | 13 / 34 | 199 / 241 |

- 영어 단어는 0.1–0.7%만 틀립니다(`dna`→움, `fu`→려, `di`→야; 일본어를 켜면 `ho`→ほ, `da`→だ, `jo`→じょ).
- 단어가 아닌 짧은 조각은 4분의 1에서 3분의 1이 바뀝니다(`ak`→마, `bb`→ㅠㅠ, `ba`→ば).
- "끔 / 켬"은 일본어 입력.

**오분리 위험.** URL이 든 한국어 말뭉치가 없어서, 기호 바로 뒤에 한글이 붙는 경우를 자막 말뭉치(ko_full, 68만
토큰)와 Tatoeba 한국어 문장 1.6만 개에서 셌습니다.

- `/`, `:`, `?`, `=`, `&`, `@` 바로 뒤 한글: 자막에서 0건(자막은 이런 기호를 거의 쓰지 않음).
- `.` 바로 뒤 한글: 자막 221토큰. 대부분 `L.A.로`, `D.C.에서`, `S.E.C.가`처럼 점 찍은 약어 + 조사와
  `안돼.안돼`처럼 띄어쓰기를 빠뜨린 문장. Tatoeba는 4건(`같아요.시간이`).
- 그 밖에 웹 글에 흔하다고 알려진 꼴: `남/여`, `TV/라디오`, `1:1문의`, `Q&A게시판`, Slack·카카오톡의 `@홍길동`.
- eval.tsv의 키에는 아래 표시가 하나도 없으므로, 그 행들의 결과는 바뀌지 않습니다.

그래서 `.`나 `/` 하나만으로는 URL이라고 보지 않습니다. 영어 + `/` + 한글(`TV/라디오`), 영어 + `.` + 조사
(`L.A.로`)가 깨지기 때문입니다.

## 규칙

띄어쓰기 없이 이어진 한 덩어리(**run**: 마지막 공백·Tab·Return·커서 이동 뒤로 친 글자)에 아래 **표시**가 있으면,
그 표시 **뒤** 조각은 판단하지 않고 친 그대로 영어로 넣습니다.

- `://` (`https://`, `ftp://`)
- run 첫머리의 `www.`
- run 첫머리의 `~/`, `./`, `../`, 또는 `/` 다음에 다시 `/`가 오는 경로(`/usr/lib`). 첫머리의 `/` 하나만으로는
  아닙니다(`/나`, Slack의 `/remind`는 어차피 영어).
- 앞에 글자가 있는 `@` (`x@`, 이메일). run 첫머리의 `@`는 아닙니다(`@홍길동` 멘션).
- `localhost:`

run 안에서는:

- 각 조각은 `Decision(.english, confidence: 1)`. 숫자 뒤 조수사(`counter after a number`)처럼, 엔진에 묻기 전에
  세션에서 정합니다. 사용자 사전도 묻지 않습니다(URL의 `so`는 사전에 `내`로 등록돼 있어도 so).
- 기호는 반각 그대로입니다. 일본어 뒤의 전각 기호 규칙(`startSymbol`)과 일본어 구절에 기호를 붙이는 규칙
  (`belongsToJapanesePhrase`)을 run 안에서는 쓰지 않습니다.
- 언어 바꾸기 키는 그대로 됩니다. 한글 경로(`wiki/서울`)는 한 번 눌러 바꿉니다. 바꾼 것은 학습하지 않습니다.
- run이 끝나면(공백 등) `previousLanguage`는 `.english`입니다.

**run을 아는 방법.** 세션이 확정하거나 앱에 넘긴 글자를 run 버퍼에 이어 붙이고, 공백·Tab·Return·`activate`·
`commitForNewContext`·방향키에서 비웁니다. 붙여 넣은 URL 뒤에 이어 칠 때는 버퍼가 비어 있으므로, 앱이 커서 앞
글자를 알려 주면(확정 뒤 고치기와 같은 수단) 거기서 공백 뒤 덩어리를 읽어 보탭니다. 알려 주지 않는 앱에서는 친
글자만 봅니다.

## 기대 효과

- 표시 뒤(경로, 쿼리, 홈 경로): 위 표의 그 줄들이 0이 됩니다. 일본어를 켰을 때 URL이 무너지는 것도 표시 뒤에서는
  없어집니다.
- 이메일의 `@` 뒤(`gmail.com`)도 표시 뒤라 지켜집니다. `ho@gmail.com`이 `ほ＠gまいl.com`이 되던 것은
  `ほ@gmail.com`까지 줄어듭니다.

## 하지 않는 것, 남는 것

- **표시 앞 조각**: 도메인(`ak.com`의 `ak`), 이메일 앞부분(`dl@`의 `dl`)은 표시를 보기 전에 확정되므로 이
  규칙으로는 못 고칩니다(위 표의 도메인·이메일 줄은 그 앞부분 탓). 확정 직후 `@`나 `.com`이 오면 방금 단어를
  영어로 되돌리는 방법이 있지만, `모.`처럼 문장 끝의 점과 구별해야 해서 따로 잽니다.
- **표시 없는 경로**: `fix/rk` 같은 브랜치 이름. `TV/라디오`와 구별할 수 없습니다. 터미널은 엄격하게나 사전으로.
- `.`나 `/` 하나로 URL을 짐작하기. 위 오분리 위험 때문에.

## 테스트

- 세션: `https://example.com/dl` → 그대로, `https://a.io/?q=dl&p=sk` → 그대로, `cd ~/src/rk` → 그대로,
  `x@gmail.com`은 `@` 뒤 그대로. 일본어 켬: `https://x.io/ho.da`에 가나·전각 없음.
- 지켜야 할 것: `@dlrjs` → `@이건`, `ska/du` → `남/여`, `TV/fkeldh` → `TV/라디오`,
  `L.A.fh` → `L.A.로`, `1:1ansdml` → `1:1문의`, 일본어 켬 `kyouha.` → `今日は。`. (지금 모두 그렇게 나옴. `Q&Arptlvks`는 지금도
  `Q&A게시판`이 아니라 그대로 영어로 남는데, 이 규칙과는 상관없는 별개 문제.)
